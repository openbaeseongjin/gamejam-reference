# 게임잼 팀 레퍼런스

팀원이 로그인 없이 읽을 수 있는 이번 게임잼용 얇은 레퍼런스 위키입니다. 개인 레퍼런스의 원문은 원래 저장소에 두고, 여기에는 팀 관점의 요약·팀 합의·이번 잼 정보만 추가합니다.

> **HTML 프리뷰:** [게시 후 확인할 주소](https://htmlpreview.github.io/?https://github.com/openbaeseongjin/gamejam-reference/blob/main/wiki/index.html) · [저장소](https://github.com/openbaeseongjin/gamejam-reference)  
> 저장소 생성과 공개 게시가 아직 확인되지 않아 프리뷰 주소는 준비된 대상 URL입니다. 공개된 `main` 브랜치에 파일을 올린 뒤 이 링크를 실제 브라우저에서 확인하고, 확인된 주소로 갱신합니다.

이 위키는 공개 저장소의 HTML을 직접 표시하는 HTML Preview를 최소 배포 경로로 사용합니다. 별도 빌드나 GitHub Actions는 추가하지 않습니다. 실제 공개 프리뷰 동작은 저장소에 게시한 뒤 확인합니다.

## 빠른 시작

- [위키 열기](wiki/index.html)
- [팀 위키 문서 템플릿](#새-문서-항목-템플릿)
- 이번 게임잼 이름·마감·제출 조건·팀원·팀 개발 규칙은 팀 합의 전까지 `미정`입니다.
- [개인 bloom-reference](https://github.com/byh-playground/bloom-reference)는 링크로만 참고합니다. 그 안의 규칙은 팀 규칙이 아닙니다.

## 문서 작성 계약

이 절은 팀 게임 규칙과 구분되는 **이 위키를 작성·편집하는 확정된 형식 계약**입니다. 사람과 AI 모두 새 항목이나 기존 항목을 편집하기 전에 이 절을 읽고 따라야 합니다.

### 상태를 구분합니다

- **팀 확정**: 팀이 합의한 내용만 씁니다. 근거가 되는 결정 기록의 영구 앵커를 함께 연결합니다.
- **논의 중**: 아직 결정되지 않은 질문과 선택지를 씁니다. 확정된 것처럼 단정하지 않습니다.
- **원본 참고**: 다른 저장소의 자료를 링크합니다. 원문을 복사하지 않으며 팀 합의로 취급하지 않습니다.
- 팀 개발 규칙은 별도 합의 전까지 `미정`입니다. 개인 bloom-reference의 규칙을 팀 규칙으로 승격하지 않습니다.

### 기존 위키 구조를 보존합니다

- `wiki/index.html`의 현재 번호 목차와 항목 순서를 유지합니다. 새 항목은 다음 번호를 쓰고, 아래 템플릿의 `id`처럼 **고유하고 바꾸지 않을 앵커**를 만듭니다.
- 목차와 본문 앵커를 함께 갱신합니다. 이미 공유한 `id`와 링크는 이름을 바꾸거나 제거하지 않습니다. 불가피한 이동은 기존 ID를 별칭으로 남기고 새 위치로 안내합니다.
- 이미 정의된 `.section`, `.wiki-section`, `.section-body`, `.status` 구성 요소와 CSS를 재사용합니다. 전역 스타일을 덮어쓰지 말고, 새 스타일이 꼭 필요하면 해당 구성 요소에만 좁게 추가합니다. 외부 CSS 프레임워크나 의존성은 넣지 않습니다.
- 각 항목은 한두 문장 요약을 먼저 보여 주고 세부 정보는 접을 수 있게 둡니다. 화면 작은 기기에서도 가로 스크롤 없이 읽히는 구조를 유지합니다.

### 내용과 근거를 씁니다

- 평이한 한국어와 짧은 문장을 사용합니다. 팀 관점의 의미·이번 게임잼에서 적용할 범위·예외를 설명하고, 일반 규칙을 길게 복제하지 않습니다.
- 개인 레퍼런스나 외부 자료를 바탕으로 한 항목은 원본 SSOT 링크를 표시합니다. 팀이 원본과 다르게 정했으면 **팀 적용 범위와 예외, 합의 근거(결정 기록 앵커)**를 함께 씁니다.
- 먼저 목차와 기존 문서를 살펴 중복을 피합니다. 새 내용을 기존 항목에 보탤 수 있으면 새 항목을 만들지 않습니다.
- 공개 저장소에 올릴 수 있는 내용만 기록합니다. 민감 정보, 비공개 대화, 승인되지 않은 개인정보는 쓰지 않습니다.

### 추가·수정 후 확인합니다

공개 프리뷰를 PC와 모바일 화면 크기에서 열고 아래를 확인합니다.

1. 번호 목차의 각 링크가 맞는 영구 앵커로 이동하고, 항목 접기·펴기가 동작합니다.
2. 템플릿을 기존 `wiki/index.html`에 붙여 넣어도 요약·상태 표식·접힘 스타일·간격이 기존 항목처럼 보입니다.
3. 넓은 화면과 좁은 화면에서 텍스트나 표가 화면 밖으로 밀리지 않습니다.
4. 새로 추가하거나 수정한 모든 외부 링크의 저장소·경로가 실제로 존재하고 열립니다.
5. 기존 링크·ID·레이아웃과 이번 변경에서 손대지 않은 참조 경로도 그대로 유지됩니다.

## 새 문서 항목 템플릿

아래 블록을 복사해 `wiki/index.html`의 `<main>` 안에 추가합니다. 새 항목 번호와 `id`를 정한 뒤, 기존 목차에도 `<a href="#new-topic">` 링크를 하나 추가합니다. 클래스는 위키에서 이미 쓰는 구성 요소이므로 별도 CSS 없이 같은 모양으로 표시됩니다.

```html
<section class="section" id="new-topic">
  <details class="wiki-section" open>
    <summary>
      <h2>6. 새 항목 제목 <span class="status status--discussion">논의 중</span></h2>
    </summary>
    <div class="section-body">
      <p class="summary">이 항목의 핵심을 한두 문장으로 요약합니다.</p>
      <p><strong>팀 적용 범위·예외:</strong> 아직 정해지지 않았다면 미정이라고 씁니다.</p>
      <p><strong>원본 SSOT:</strong> <a href="https://example.com/source">원본 문서명</a></p>
      <p><strong>합의 근거:</strong> <a href="#decisions">결정 기록 앵커</a> 또는 미정</p>
    </div>
  </details>
</section>
```

개인 참고를 새로 추가하는 항목은 상태를 `원본 참고`로 표시하고 팀 확정 표현을 쓰지 않습니다. 합의를 마친 내용은 상태를 `팀 확정`으로 바꾸고 `#decisions`에 결정 근거를 남깁니다.
